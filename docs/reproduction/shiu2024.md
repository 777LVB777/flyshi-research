# Shiu et al. (2024) reproduction setup

## Scope

This records an installation and minimal smoke test of the upstream model only.
It adds no market, agent, reward, or plasticity code.

## Source

- Paper: Shiu et al., *Nature* 634, 210–219 (2024),
  doi:10.1038/s41586-024-07763-9.
- Upstream repository: `https://github.com/philshiu/Drosophila_brain_model`
- Upstream commit: `91bdd1e7dcf193f3e7ca5a8933497fcef63b7960`
- License: MIT (as supplied by upstream).
- Data: the upstream checkout's FlyWire v630 completeness CSV and connectivity
  Parquet files.

## Platform

- macOS 26.4 (build 25E246), Darwin 25.4.0.
- CPU architecture: arm64. The local hardware-model query was restricted, so
  the exact Apple chip model is unverified.
- Compiler: Apple clang 21.0.0 (`arm64-apple-darwin25.4.0`).
- Environment: `.venv-shiu`, created by uv with CPython 3.10.21.

## Python-version decision

The upstream `environment.yml` pins Python 3.10 (and Brian2 2.5.1); its full
manifest records Python 3.10.11. The original requested Python 3.11 environment
was therefore not used. Python 3.10 was chosen to match upstream, with the
explicit decision supplied for this setup.

## Commands

From the repository root:

```bash
git clone https://github.com/philshiu/Drosophila_brain_model third_party/Drosophila_brain_model
git -C third_party/Drosophila_brain_model rev-parse HEAD
uv venv .venv-shiu --python 3.10
uv pip install --python .venv-shiu brian2==2.5.1 'numpy==1.24.*' pandas joblib pyarrow
uv pip install --python .venv-shiu setuptools==67.8.0 cython==0.29.33
uv pip freeze --python .venv-shiu
clang --version
uv run --python .venv-shiu/bin/python --no-project -- .venv-shiu/bin/python repro/shiu2024/smoke_test.py
```

`requirements-lock.txt` is the exact resolved package set. The requested
direct dependencies resolved to Brian2 2.5.1, NumPy 1.24.4, pandas 2.3.3,
joblib 1.6.0, and pyarrow 25.0.1. The first Brian2 import failed because the
resolver selected setuptools 84.0.0, which no longer exports `pkg_resources`.
Pinning setuptools 67.8.0 inside this isolated environment restored the module;
this is also the setuptools version recorded in upstream's full manifest. No
platform-specific packages from `environment_full.yml` were installed.

Cython was initially resolved to 3.3.0. Brian2 2.5.1 then fell back to NumPy,
reporting `Cython is not available (ImportError)` during its compilation test.
It was replaced with upstream's Cython 0.29.33 pin. The full-manifest versions
matched by this environment are Brian2 2.5.1, Cython 0.29.33, and setuptools
67.8.0. Intentional or resolver-derived differences include CPython 3.10.21
(upstream: 3.10.11), NumPy 1.24.4 (1.22.3), pandas 2.3.3 (1.4.3), joblib 1.6.0
(1.2.0), pyarrow 25.0.1 (11.0.0), SymPy 1.14.0 (1.12), and their transitive
dependencies. NumPy 1.24.x follows the non-platform-specific `environment.yml`
requirement; pandas, joblib, and pyarrow were unpinned there.

## C++ and Brian2 code generation

`clang --version` completed successfully. Before the Cython pin, Brian2 reported
an `auto` target but failed its Cython compilation test with `Cython is not
available (ImportError)` and fell back to NumPy. After installing Cython 0.29.33,
a minimal Brian2 run created a `CythonCodeObject`; C++/Cython runtime code
generation is therefore available in `.venv-shiu`. No Brian2 upgrade or compiler
configuration change was made.

## Full-default sugar validation

The upstream notebooks identify 21 right-hemisphere labellar sugar GRNs as the
input set. `figures.ipynb` identifies MN9 as the feeding readout; MN9 controls
rostrum lifting during proboscis extension. Its FlyWire IDs are
`720575940660219265` (left, contralateral to these right-hemisphere inputs) and
`720575940645521262` (right, ipsilateral). The unchanged `default_params` are
1,000 ms per trial, 30 trials, and 150 Hz stimulation. The prose in
`example.ipynb` says 200 Hz, but its unmodified `sugarR` call uses
`default_params`; this documentation uses the code-defined 150 Hz value.

`repro/shiu2024/validate_sugar.py` resets NumPy and Brian2 to seed `20260316`
before each of two serial, full-default repetitions. It uses no altered neural,
synaptic, or stimulation parameters and ranks responders after excluding all 21
stimulated GRNs.

**Validation result: PASS (qualitative reproduction).** A normal-terminal run
completed two serial, seeded repetitions using FlyWire v630, 30 trials of
1,000 ms, 150 Hz stimulation, seed `20260316`, and `n_proc=1`. Cython code
generation was enabled. The runs produced identical seeded results: 410,625
spikes each. Runtime was 785.953 s (reported by upstream as 782 s) and 824.901
s (823 s), respectively.

| Metric | Local validation | Bundled author `results/example/sugarR.parquet` |
| --- | ---: | ---: |
| MN9 left (contralateral) | 83.87 Hz | 93.27 Hz |
| MN9 right (ipsilateral) | 57.07 Hz | 61.80 Hz |
| Left/right MN9 ratio | 1.47 | 1.51 |
| Spike count | 410,625 | 511,566 |

The top three downstream (non-input) responders match the bundled author output
in identity and order:

| Rank | FlyWire ID | Local rate (Hz) | Bundled rate (Hz) |
| --- | --- | ---: | ---: |
| 1 | 720575940622695448 | 138.83 | 156.77 |
| 2 | 720575940629888530 | 127.10 | 146.50 |
| 3 | 720575940627383685 | 124.23 | 141.23 |

The expected contralateral-over-ipsilateral MN9 ordering and top-three identity
ordering reproduce. The local dominant downstream rates are consistently about
10–12% lower than the bundled output (left MN9 is 10.1% lower; right MN9 is
7.7% lower); the source of this difference is unexplained. The paper cautions
that absolute firing-rate predictions are unlikely to be accurate, and it does
not provide a 150 Hz numerical MN9 target for direct comparison here.

Read-only source investigation: `model.py` directly defines `t_run=1000*ms`,
`n_run=30`, and `r_poi=150*Hz`; `example.ipynb` directly uses the v630 files
and calls `run_exp(exp_name='sugarR', neu_exc=neu_sugar, **config)` without a
parameter override. `figures.ipynb` directly uses the same 21 right sugar GRNs,
v630 files, and a 10–200 Hz Figure 1D sweep. Neither notebook nor `model.py`
contains seed handling. The `example.ipynb` configuration specifies `n_proc=-1`
and `figures.ipynb` specifies `n_proc=15`, unlike this validation's `n_proc=1`.
The notebook prose says the default stimulus is 200 Hz, conflicting with the
code-defined 150 Hz. It is therefore **unverified** that the bundled output was
created with exactly 150 Hz, 30 trials, 1,000 ms, or either parallel setting;
the code supports but does not record that provenance. FlyWire v630 is directly
shown by the two `2023_03_23_*_630_final` input filenames.

The requested Edmond archive DOI (10.17617/3.CZODIW) was not independently
retrieved: its public page returned an access-denied response. Accordingly,
archive-specific provenance and reference values remain unverified.

## Operational notes

- Codex-launched simulations can keep running after a timeout. Before starting
  a run, check `ps aux | grep validate_sugar`.
- Run long simulations in a normal terminal, not inside Codex.
- On this 8 GB Apple Silicon Mac, the validation took about 26 s per simulated
  1-s trial. Peak memory footprint was about 4.7 GB and the run reported zero
  swaps. Upstream appears to rebuild the network each trial; this is unverified
  from its implementation and has not been profiled independently.
